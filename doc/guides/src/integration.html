1Concepts and imports

Chronoverse has two layers:

ImportContainsUse it for
package:chronoverse/chronoverse.dartEverything: widgets, dialogs, theme, plus the whole core.Flutter apps.
package:chronoverse/core.dartPure Dart: Chrono, extensions, formatting, parsing, conversions, time zones, events, recurrence, iCalendar.Business logic, servers, command-line tools, isolates, tests.

Naming is consistent: widgets start with Chrono (ChronoCalendar), dialogs with showChrono, and data classes describe what they hold (DateRange, CalendarEvent, RecurrenceRule). All dates are plain DateTime values; day-based APIs ignore the time part.

Every option has a sensible default. Start with the smallest code and add options only when you need them.

2The month calendar

ChronoCalendar(
  initialDate: DateTime(2026, 10, 1),
  firstDay: DateTime(2020),                 // navigation limits
  lastDay: DateTime(2030, 12, 31),
  mode: ChronoSelectionMode.single,         // none, single, multiple, range
  initialFormat: ChronoCalendarFormat.month, // month, twoWeeks, week
  expandable: true,                         // handle to expand/collapse
  formatToggle: true,                       // month / 2 weeks / week button
  showWeekNumbers: true,
  sixWeekMonths: true,                      // constant height
  holidayPredicate: (d) => d.month == 12 && d.day == 25,
  onDaySelected: (day) => print(day),
  onPageChanged: (focused) => print('Now showing $focused'),
)

What users can do

  • Swipe left or right (touch, mouse drag or trackpad), or use the arrows, to change month or week.
  • Tap the title to open a year grid, then a month grid, to jump anywhere quickly.
  • Drag the handle down to expand to a month, up to collapse to a week.
  • Use the keyboard: arrows move between days, Page Up / Page Down change the page.
  • Tap "today" in the header to return to the current date.

3Controlling the calendar from code

Create a ChronoCalendarController to read and change the calendar from anywhere. It is a ChangeNotifier, so you can listen to it.

final controller = ChronoCalendarController(
  focusedDay: DateTime.now(),
  format: ChronoCalendarFormat.week,
  mode: ChronoSelectionMode.single,
);

ChronoCalendar(controller: controller, expandable: true);

controller.showWeekOf(DateTime(2026, 12, 21)); // collapse to that exact week
controller.expand();                          // full month
controller.collapse();                        // back to the focused week
controller.toggleExpanded();
controller.setFormat(ChronoCalendarFormat.twoWeeks);
controller.jumpTo(DateTime(2027, 3, 1));
controller.nextPage();
controller.previousPage();
controller.today();

controller.select(DateTime(2026, 10, 20));
controller.selectRange(DateRange(DateTime(2026, 10, 1), DateTime(2026, 10, 7)));
controller.selectDays([DateTime(2026, 10, 2), DateTime(2026, 10, 9)]);
controller.clearSelection();

controller.selectedDay;     // DateTime?
controller.selectedDays;    // Set<DateTime>
controller.selectedRange;   // DateRange?
controller.isExpanded;

controller.addListener(() => print(controller.focusedDay));
// Dispose it in your State.dispose().
If you do not pass a controller, the calendar creates and disposes its own.

Selection modes

ChronoCalendar(
  mode: ChronoSelectionMode.range,
  maxRangeDays: 14,           // days beyond the limit are greyed while picking
  onRangeSelected: (range) {
    if (range != null) print('${range.lengthInDays} days');
  },
)

Which days can be picked

DateAvailability describes blocked and allowed days in one object. It is shared by the calendar, the dialogs, the date field, the strip and the vertical calendar.

final availability = DateAvailability(
  disablePast: true,
  disabledWeekdays: {DateTime.sunday},
  disabledDates: [DateTime(2026, 12, 25)],
  disabledRanges: [DateRange(DateTime(2026, 11, 3), DateTime(2026, 11, 6))],
  predicate: (day) => day.day != 13,     // any rule
);

availability.isAvailable(DateTime(2026, 12, 25));   // false
availability.isRangeAvailable(someRange);           // false if any day inside is blocked
availability.nextAvailable(DateTime.now());         // first free day

ChronoCalendar(availability: availability);

To allow only certain days, use enabledDates. A range that would cross a blocked day is rejected automatically.

5Events on the calendar

Pass a list of CalendarEvent objects, or an eventLoader that returns items for a day. Repeating events are expanded automatically and indexed once per visible page, so even thousands of events stay fast.

final events = [
  CalendarEvent.allDay(id: '1', title: 'Holiday', start: DateTime(2026, 10, 2), color: 0xFF10B981),
  CalendarEvent(
    id: '2',
    title: 'Design review',
    start: DateTime(2026, 10, 14, 10),
    end: DateTime(2026, 10, 14, 11, 30),
    color: 0xFF6366F1,
    recurrence: RecurrenceRule.weekly,
  ),
];

ChronoCalendar(
  events: events,
  markerStyle: ChronoMarkerStyle.dots,   // dots, bars or chips
  onDaySelected: (day) => print(events.on(day).map((o) => o.event.title)),
);

// Or load anything you like:
ChronoCalendar(eventLoader: (day) => myDatabase.itemsFor(day));

Each event's color is used for its marker; otherwise markerColor or the theme's eventColor is used.

6Planner cards and drag & drop

Set markerStyle: ChronoMarkerStyle.chips to show titled, coloured cards inside each day. Give the cells more height so the cards fit.

ChronoCalendar(
  events: events,
  markerStyle: ChronoMarkerStyle.chips,
  chipStyle: const ChronoChipStyle(
    shape: ChronoChipShape.accentBar,  // rounded, pill, square, accentBar, outlined
    height: 16,
    fontSize: 10,
  ),
  theme: const ChronoThemeData(cellHeight: 92, dayShape: ChronoDayShape.square, cellPadding: 0),
  onItemTap: (item) => openDetails(item),
  onDrop: (day, data) => handleDrop(day, data),
  canDrop: (day, data) => !day.isWeekend(),  // optional rule
)

Dragging notes in from your UI

Wrap any widget in ChronoDragItem. Long-press (or drag directly with longPress: false) and drop it on a day. The target day highlights while hovering.

ChronoDragItem<String>(
  data: 'Pay rent',
  child: Chip(label: Text('Pay rent')),
);

void handleDrop(DateTime day, Object data) {
  if (data is String) {
    setState(() => events.add(CalendarEvent.allDay(id: uuid(), title: data, start: day, color: 0xFFF59E0B)));
  } else if (data is EventOccurrence) {
    // A card was moved from another day: shift the event.
    final shift = data.start.daysUntil(day);
    // update data.event.start / end by shift days and save
  }
}

Cards that do not fit show a "+n" indicator. Your own objects work too: return them from eventLoader and provide itemLabel to give each one a title.

10Languages and right-to-left

Fourteen languages are built in: en es fr de it pt ru ar hi mr zh ja ko tr. Each one provides month and weekday names, the first day of the week, weekend days, date order, plural rules, relative-time phrases, button labels and native digits.

// Follows the app's locale automatically, or set it:
ChronoCalendar(locale: ChronoLocale.of('ar'), nativeDigits: true);

Chrono.format(DateTime.now(), 'EEEE d MMMM yyyy', locale: 'de');   // Dienstag 20 Oktober 2026
Chrono.timeAgo(DateTime.now().subtract(const Duration(hours: 5)), locale: 'fr');

Right-to-left languages mirror automatically under a right-to-left Directionality, including swipe direction and arrow keys.

Adding a language

Create a ChronoLocale with your translations (copy a built-in one as a starting point) and register it once at start-up:

ChronoLocale.register(myLocale);
ChronoLocale.of(myLocale.code);   // now available everywhere

13Time zones

ChronoTimeZone includes about 60 common zones with daylight-saving rules for North America, Europe, Australia and New Zealand. Gaps (clocks jump forward) and overlaps (clocks fall back) are handled.

final kolkata = ChronoTimeZone.get('Asia/Kolkata');
final newYork = ChronoTimeZone.get('America/New_York');

final meeting = kolkata.fromWall(2026, 10, 20, 19, 30);   // ZonedDateTime
kolkata.convert(DateTime(2026, 10, 20, 19, 30), newYork);  // same instant in New York
newYork.isDst(DateTime.now().toUtc());
newYork.offsetLabel(DateTime.now().toUtc());               // UTC-04:00
ChronoTimeZone.ids;                                        // every known id

// Add or override a zone
ChronoTimeZone.register(const ChronoTimeZone('Europe/Example', Duration(hours: 1), dst: DstRule.europe));

// Fixed offsets
ZonedDateTime.tryParse('2026-10-20T09:00:00+05:30');
Time-zone rules change by government decision. Keep the package up to date and verify any time-critical conversion. Register a corrected zone with ChronoTimeZone.register if a rule changes before an update is available.

14App architecture and state

  • Keep dates in your state, not in widgets. Store the selected date or range in your own state object and pass it down, or listen to a ChronoCalendarController.
  • The controller is a ChangeNotifier, so it fits any state-management approach that works with listenable objects, including plain setState, ValueListenableBuilder / ListenableBuilder, and inherited widgets.
  • Put business rules in the core. Availability, recurrence and date math come from core.dart, so they can be unit-tested without widgets and reused on a server.
  • Store dates in UTC or ISO 8601 (Chrono.toIso) and convert to local or zoned time only for display.
  • Use data on CalendarEvent<T> to carry your own model, so callbacks give you your object back without lookups.
ListenableBuilder(
  listenable: controller,
  builder: (context, _) => Text(Chrono.format(controller.focusedDay, 'MMMM yyyy')),
)

15Performance, accessibility and testing

Performance

  • Pass events rather than a slow eventLoader; Chronoverse indexes them per page.
  • If you use eventLoader, make it a fast map lookup (for example from groupByDay).
  • Keep the same list instance when nothing changed, and create a new list when something did.
  • Use const ChronoThemeData(...) where possible.

Accessibility

  • Every day has a screen-reader label with the full date and its state (selected, today, unavailable).
  • Text scales with the system font size without overflowing.
  • All interaction is available from the keyboard, and colours come from your accessible color scheme.

Testing your integration

testWidgets('picks a day', (tester) async {
  DateTime? picked;
  await tester.pumpWidget(MaterialApp(home: Scaffold(body: ChronoCalendar(
    initialDate: DateTime(2026, 10, 1),
    onDaySelected: (d) => picked = d,
  ))));
  await tester.tap(find.text('15'));
  expect(picked, DateTime(2026, 10, 15));
});

Pass a fixed initialDate in tests so results do not depend on the current day.
